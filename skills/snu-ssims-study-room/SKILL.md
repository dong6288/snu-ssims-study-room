# 서울대 스터디룸 예약

Use the student's regular Chrome through the supported `@Chrome` extension. Open [예약하샤](https://ssims.snu.ac.kr/index.do) in a task tab, or use the official tab the student selected. Read [the browser workflow](references/ssims.md) for live controls, evidence, and Korean student messages. Use the current signed-in student's personal qualification. Let the student handle sign-in, qualification selection and protected participant inputs directly in Chrome. Resume after they return control and you verify the official screen. Keep credentials and participants' personal data out of chat, tools used for summaries, and the local journal.

## 예약 요청과 필수 동의

이 스킬은 학생이 예약하샤의 일반적인 `개인정보 수집 및 이용동의`와 `공간 사용 안내사항`을 숙지하고 동의한 상태에서 예약을 맡기는 흐름입니다. `예약해줘`·`신청해줘`는 신청자 본인에게 적용되는 두 항목의 체크와 해당 무료 예약 한 건의 제출까지 포함합니다. 처음 사용하는 채팅에서도 공식 화면의 두 항목을 확인해 체크하고, 같은 신청의 동의·최종 확인창까지 이어서 처리합니다. 신청 내용을 짧게 안내한 뒤 같은 턴에서 제출하고 공식 결과를 확인합니다. 같은 조건의 동의나 제출 승인을 다시 요청하며 기다리는 단계를 두지 않습니다.

Honor a student's explicit refusal or withdrawal. Follow the [acknowledgment rules](references/ssims.md#4-prepare-and-submit-one-application) for materially different terms, another person's information and an actual host approval block. For a booking in an existing chat that loaded an earlier skill version, refresh this installed file and the browser workflow before acting.

## Find a room

Use read-only lookup for unclear intent. Resolve only the missing or ambiguous details needed for the requested action and group them in one question when practical. State the interpreted date, time in KST and location scope. Use 관악 if the student omitted location. A request for all campuses covers every visible campus tab. A request with building omitted covers `건물명 전체` and `호실명 전체` in the applicable campus.

Use a stated group size to check the room's capacity and eligibility. When the student wants only the requested time fixed and delegates registration details, or requests applicant-only registration, default to just the applicant where the official form and room rules permit it. Follow the [registration rules](references/ssims.md#4-prepare-and-submit-one-application) for forms that ask for actual attendance. Request individual registrations only when required.

Scan every result page to discover rooms without a building allowlist. Check the scope after navigation and confirm the requested use, eligibility, capacity, equipment and time conditions. Report short results in Korean using the evidence labels in the browser workflow. Include KST observation time, scope and page coverage. If no match was verified, explain any confirmed reason and offer the next useful choices. Central Library users can continue in the [official library app](https://lib.snu.ac.kr/about/mobile/mobile-pass/).

## Apply for one room

For a search-only request stop at results. For an explicit application request, honor the exact requested date, interval and any named requirements. Choose a suitable free room when the student leaves that choice open. Select the official purpose closest to the stated use, or a permitted general study-room purpose if no specifics were provided. Use a truthful short title and description. Run the read-only [Node and journal preflight](references/journal.md) before writing the form or asking for protected inputs. If preflight fails, explain the setup step and limit the work to lookup and recovery. Verify full-interval calendar coverage, the official form, the local interval and the student's existing reservations. During any handoff ask the student to return before pressing `예약신청하기`. If they already pressed it or the screen suggests prior submission, stop. Record a local hold for the exact known interval and reconcile under the browser workflow.

Use the booking request as the submission authorization described above. A student's choice from offered times completes that request for the selected candidate. Recheck the complete form and current evidence, select both customary acknowledgments and continue through the same application's final confirmation. If intent, material terms or form values go outside the request or materially change after they were established, resolve only the affected items.

Read [the local attempt journal instructions](references/journal.md) before the first click that can submit. Obtain a new attempt ID and successful `claimed` result from the journal immediately before using the official final action. An existing, failed or ambiguous journal result leaves the task in lookup or reconciliation. In the same run, an unambiguous official pre-submission confirmation can complete the same approved application. A new chat never repeats an unresolved attempt.

Verify the new application against the official result or `나의예약현황`. Give its evidence-based status and next action. While the outcome is unclear, keep any unresolved journal record and stop both automatic retries and advice to submit manually. When work stops, explain why, what remains visible in Chrome, and the safe next action.

## Cancel one booking

A clear `예약 취소해줘` authorizes cancelling one uniquely identified booking in the student's own `나의예약현황`. Use the [cancellation workflow](references/ssims.md#5-cancel-one-booking). Resolve only ambiguity about the target or material terms. Verify the official outcome for the same record before reporting success or releasing its local journal hold. If the record is already cancelled, report that status without another click.
