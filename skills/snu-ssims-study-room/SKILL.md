# 서울대 스터디룸 예약

Use the user's regular Chrome through the supported `@Chrome` extension. Open [예약하샤](https://ssims.snu.ac.kr/index.do) in a task tab, or use the official tab the user selected. Read [the browser workflow](references/ssims.md) for live controls, search coverage, evidence, and reservation boundaries. Use the current signed-in student's personal qualification. If sign-in, qualification selection, or protected input is needed, hand the official Chrome tab to the user and resume only after they return control and you verify the official screen. Keep credentials and participants' personal data out of chat, tools used for summaries, and the local journal.

## Find a room

Normalize the KST date, use time or flexible range with required duration, headcount, location, mandatory and preferred equipment, and whether the student asked to search or apply. For an application collect the real use purpose. Ask only for missing details necessary for the requested action. Use 관악 if the location is unspecified and state that assumption. A request for all campuses covers every visible campus tab. A request with building omitted covers `건물명 전체` and `호실명 전체` in the applicable campus.

Scan every result page to discover rooms without a building allowlist. Check the scope after each navigation. Evaluate explicit study rooms and other rooms advertised for the requested use, user eligibility, operating and exit times, capacity, quotas and equipment. Room labels and a blank calendar have limited meaning. Report what you verified, KST observation time and coverage, and official links. Distinguish confirmed availability, exact application form checked with no overlap, unverified candidate, conflict, and no results. Central Library users can continue in the [official library app](https://lib.snu.ac.kr/about/mobile/mobile-pass/).

## Apply for one room

For a search-only request stop at results. For a reservation request select one room within the constraints, verify both full-interval calendar coverage and the official application form, and check the student's existing reservations. Show the completed free application after the student has entered any required personal information and checked required consents. Get agreement on the exact room, KST time, count, purpose, title, body, fees, and material terms. Recheck the original signed-in tab and approved form. Refresh the slot evidence before submission and stop if any required evidence has become unavailable.

Read [the local attempt journal instructions](references/journal.md) before the first click that can submit. Obtain a new attempt ID and successful `claimed` result from the journal immediately before using the official final action. An existing, failed or ambiguous journal result leaves the task in lookup or reconciliation. In the same run, an unambiguous official pre-submission confirmation can complete the same approved application. A new chat never repeats an unresolved attempt.

Verify the new application in the official result or `나의예약현황`. Report `신청 접수`, `승인 대기`, `예약 확정`, `미접수`, `반려`, `취소`, or `결과 확인 필요` based on the actual screen and its relationship to this attempt. Keep ambiguous attempts in the journal and avoid a second submission. For paid rooms, payments, terms needing user approval, unsupported actions, or unreadable screen states, hand off the exact official step with context.
